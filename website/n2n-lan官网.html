N2N · 房间式虚拟局域网

把远方的电脑，
变成同一个房间

不同网络、不同账号的两台电脑，通过你自己的服务器进入同一个「房间」—— 在游戏眼里你们就在同一张局域网里。专门为 MC 等支持局域网模式的游戏异地联机而做。

开黑房的正确打开方式

不为联机折腾公网 IP、端口映射和繁琐配置——一个房间码，朋友粘贴即可进房。

朋友不用装 Python

PyInstaller 打包成单文件 exe，内含运行环境；把客户端 zip 发给朋友，解压双击 start.bat 就能进房。

密码房 / 免密房

房主可勾选「带密码」：自动生成 6 位数字密码并参与加密密钥派生——密码错误 = 密钥不同 = 进不来，房间码泄露也没用；不勾就是免密房。

P2P 直连

supernode 只负责「房间登记 + NAT 打洞」，双方打洞成功即 P2P 直连，低延迟不占服务器带宽；打洞失败自动降级服务器中转。

中英双语界面

自动检测系统语言：中文系统显示中文，英文系统显示英文；也可在「工具与设置 → 语言」随时切换，老外朋友零门槛使用。

Linux 也能进同一个房

附一键进房脚本（join_room_linux.sh），Windows 房主 + Linux 好友同房间互通；下载预编译 n2n v3 edge 即可。

开源可审计

房间管理工具与部署脚本采用 MIT 协议，n2n 引擎 GPLv3、TAP 驱动 GPLv2，来源与许可全部在仓库里写清，可自行复查。

它是怎么把两台电脑变成同一个房间的

一个公网服务器做「房间前台」，登记谁在哪个房间、帮双方打通 NAT——之后你们就直接对话。

  1. 服务器只做「前台」

    部署一个公网 supernode（Linux 一键脚本 / Windows bat / Docker 都行），它只登记房间成员、帮忙打通 NAT，不碰你的游戏流量。

  2. 房间码 = 房间的身份

    房主创建房间自动生成房间码（community@网段#密钥），密钥即传输加密口令；带密码房间再叠加 6 位数字密码。

  3. 进房后 P2P 直连

    双方都拿到虚拟 IP（10.x.0.x），打洞成功就直连互访；打洞失败自动降级为服务器中转，房间依然可用。

三步开黑

从部署到进游戏，全程大约十分钟。完整的服务器部署与排障说明在仓库 README 里。

01

部署公网服务器

有公网 IP 的机器（云服务器或家庭宽带+端口转发）跑一个 supernode：
bash deploy_supernode.sh
Windows 服务器就双击 start_supernode.bat。

02

房主创建房间

打开房间管理小工具，填服务器地址并保存，点「创建房间」。自动生成房间码；勾选「带密码」则再生成 6 位密码，密码单独发给好友。

03

好友粘贴进房

好友粘贴房间码（带密码房再填密码），点「加入房间」自动分配虚拟 IP。双方显示「已连接」后，MC 里直接连接 10.x.0.1:25565 即可。

常见问题

几句话讲清最容易踩的坑。

家里没有公网 IP，还能用吗？

能。家庭宽带最常见：路由器做「端口转发」，把 UDP 7654 转发到服务器内网 IP（比如 192.168.1.4），客户端统一填你的公网 IPv4:7654 即可；公网 IP 会变就配个 DDNS。改不了路由器就用公共 supernode 节点（README 有说明）。

为什么不能只把 exe 发给朋友？

exe 需要同目录的 bin/（edge 引擎）、driver/（TAP 虚拟网卡驱动）、tools/ 一起工作。请把整个解压后的文件夹发给对方，或直接发 zip。

双方都显示「已连接」但游戏里看不到对方？

先确认房间码网段一致、密码正确（密码错 = 密钥不同 = 进不来）；再确认 MC 版本和模组完全一致。版本一致还看不到，就用「直接连接」填房主虚拟 IP:25565，绕开局域网发现。

延迟高、卡顿怎么办？

延迟高通常是 NAT 打洞失败走了服务器中转。换离双方都近的服务器地域，或在设置里把 MTU 调低到 1200 再试；房间成员建议不超过 10 人。
